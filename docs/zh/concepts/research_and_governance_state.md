# 研究状态与治理状态

一次 ARI 运行在任一时刻都不止有一种状态，而这些状态回答的是不同的问题。
「该运行仍在执行」「该运行已进入论文阶段」「该运行的治理记录已降级」以及
「该节点的得分不再算数」是四个彼此独立的事实。把其中任意两个混为一谈，都会
产生一个 ARI 无法支撑的断言。

本页是这些区分在概念上的归属地。仪表盘的真实性规则 —— 那些标签、那些分开的
行、拒绝画出一条连续得分曲线的做法 —— 都由它推导而来，而它同样适用于任何
手工阅读检查点的人。

相关页面：[仪表盘架构](gui_architecture.md) 讲这些规则如何在 UI 中被强制，
[Constitutional ARI-RQGM 架构](rqgm_architecture.md) 讲产生这些治理工件的
内核。

---

## 1. 四台状态机，而不是一台

| 状态机 | 它回答的问题 | 作用域 | 存在于 |
|---|---|---|---|
| 运行生命周期 | 这次运行现在还在执行吗？ | 一个运行 | 每一次运行 |
| 研究阶段 | 它在研究流水线上走到哪一步了？ | 一个运行 | 每一次运行 |
| 治理阶段 | 当前生效的是哪个受治理纪元与得分策略？ | 一个运行 | 仅 `ari_rqgm` 运行 |
| 节点得分状态 | 这个节点的得分还算数吗，在哪个策略之下？ | 一个节点 | 仅 `ari_rqgm` 运行 |

它们因不同的原因、在不同的时刻推进，而且没有任何一台蕴含另一台。一次运行
可以是 `running` 却尚无阶段，可以是 `completed` 而其治理记录已降级，也可以
既受治理又健康，而其中某一个特定节点的得分被失效。

---

## 2. 运行生命周期与研究阶段

两者都从已提交的工件只读推导 —— 仪表盘中没有任何东西*记录*生命周期或阶段。

**运行生命周期**按检查点目录推导：该运行存在活跃进程即为 `running`；否则由
节点树决定 —— 树中仍显示 `running` 但没有活跃进程，就是被遗弃的 `stopped`，
一棵已被填充的树是 `completed`，而存在 `review_report.json` 同样把它定为
`completed`。在没有依据可循时，诚实的答案是 `unknown`。

| 取值 | 含义 |
|---|---|
| `running` | 找到了该运行的活跃进程 |
| `stopped` | 树中说某个节点在运行，但没有进程存活（被遗弃） |
| `completed` | 树已被填充且没有运行中的节点，或者存在评审报告 |
| `unknown` | 证据不足 —— 有意不默认为「completed」 |

**研究阶段**是一次独立的、基于工件存在性的推导：存在评审报告即 `review`；
存在论文（或流水线已启动）即 `paper`；存在 idea 工件即 `bfts`；什么都还没有
则完全没有阶段。UI 渲染的冻结阶段词汇表是 `idle`、`starting`、`bfts`、
`paper`、`review`，其中「尚未推导出阶段」显示为 `idle`。

两者有意是正交的。`stopped` + `paper` 是一个完全自洽的状态（流水线在论文写好
之后被中断），`running` + `idle` 也一样（运行刚刚开始，磁盘上还什么都没有）。

---

## 3. 治理阶段是另一条时间线

对于在 `ari_rqgm` 执行模式下执行的运行，还存在一个*治理阶段*：当前开启的
纪元与生效的效用策略哈希，读自已提交治理转换的重放。

由它是一台独立状态机所推出的规则：

- **它被渲染成自己独立的带标签行**，绝不并入研究阶段。一次运行的阶段对它的
  纪元一无所言，而纪元对它的阶段也一无所言。
- **它对 `simple_bfts` 运行不存在。** 这里的缺失是一种能力状态 ——
  「governance is not active for this run」并附上原因 —— 而不是错误，也不是零。
- **治理已接受 ≠ 研究已完成。** 一次治理转换成功提交，意味着该机构遵守了它
  自己的规则。它对科学是否奏效不作任何断言。
- **执行模式与论文模式是独立的两个轴。** 一次运行要么受治理要么不受治理
  （`ari.mode`），同时另外还使用归档论文流程或线性流程；四种组合都有效。

### 「治理受阻」**不**意味着什么

当治理读模型报告降级理由或某条完整性链失败时（转换链、注册表快照、审计链
—— 每一条都是三态的：已校验 / 已断裂 / 来源缺失），仪表盘会呈现治理阻塞项。
这是最容易被误读的信号之一，因此这里把它说清楚。

一个治理阻塞项意味着：**治理记录的某些部分缺失、不一致，或者其哈希链校验
失败。** 这是一个关于治理*工件*的陈述。

它**不**意味着：

- 研究运行失败了，或产生了糟糕的结果；
- 运行停止了，或卡住了；
- 某个组件被制裁、隔离或封禁（那些是注册表生命周期事件，有它们自己的状态
  —— §4）；
- 页面上别处展示的结果是错的。

反过来误读同样是错的：**记录到零次攻击是一个数据点，而不是健康的证据。**
如果一次运行中已注册的对抗者只能针对不受治理的角色，那么它的弹劾链在结构上
就是惰性的 —— 该链按设计*无法*触发，因此它的沉默什么也证明不了。这同样是
一种能力状态，并被如此标注。

## 4. 注册表生命周期 vs 节点得分状态

这是两套最常被混淆的词汇表，因为二者有时都被叫做「状态」。它们是彼此独立的
状态机，绝不会被混进同一个字段 —— 在 API 中它们是两个不同的闭合类型，因此
注册表状态甚至无法被*表示*在一个节点状态字段中。

**注册表组件生命周期** —— 一个*受治理组件或提示词*（某个角色的实现）的
状态。这是一个十值的闭合词汇表，按其声明顺序逐字镜像自内核：`candidate`、
`validated`、`shadow`、`probationary_active`、`active`、`warning`、
`probation`、`quarantine`、`retired`、`banned`。大致而言，前五个是准入路径，
后五个是制裁路径；它们之间的转换是内核规则，不是 UI 的关切，而仪表盘只会
重放已经被提交的内容。

**节点得分状态** —— *单个节点得分*的状态，一个五值词汇表：

| 状态 | 含义 |
|---|---|
| `computed` | 在该纪元的策略下正常评分 |
| `recomputed` | 基于幸存输入重新评分（记录中写明是哪个纪元） |
| `stale` | 被一个已退役组件污染 —— 不再参与前沿评分 |
| `invalidated` | 该得分所依据的策略已被取代 |
| `removed` | 已从前沿中撤出 |

问责一侧还适用另外两条纪律规则，并且它们是被结构性强制的，而不是靠约定：

- **原始攻击永远不可能携带数值。** 原始对抗断言与经过裁决的断言是不同的
  记录种类；原始那一类根本没有得分、惩罚或置信度字段，它的「claimed
  severity」是攻击者的断言，而不是惩罚。只有经过裁决的已验证攻击才能驱动
  惩罚。
- **当前状态就是已提交内容的重放。** rollup 快照被读取，只是为了检查它与
  重放一致；未提交的尾部永远不会被采纳。

## 5. 得分只有在同一个策略内部才可比

仪表盘展示的每一次得分观测都携带它所依据的**效用策略哈希**。该哈希是规范
策略正文的内容哈希，因此两个不同的哈希意味着两个字面意义上不同的评分函数。

这不是一个展示上的小讲究。在 `ari_rqgm` 模式下，一次纪元边界可以改写效用
函数本身，其后果是*整个得分被改写* —— 包括那些从未被攻击过的节点。在策略
`A` 下算出的数字与在策略 `B` 下算出的数字，不是同一条曲线上的两个点；它们是
来自两台不同仪器的两次测量。

由此推出的规则：

- **任何得分都不会脱离其策略身份展示。** 是「Score under policy `<hash>`」，
  绝不是一个裸的数字。
- **不同的策略哈希被分面，绝不被合并。** 每个哈希各占一组；跨越一次策略变更
  不存在单一连续序列，而且根本不提供跨纪元的得分比较。
- **两条谱系通道保持分离。** 通道 1 是纪元*内部*的对抗惩罚（基础分 →
  已验证惩罚 → 最终分，以经过裁决的记录 id 作为证据）。通道 2 是纪元边界的
  策略改写。它们是两个独立列表，正是为了让任何消费者都无法意外把它们合并成
  同一段历史。
- **重算在原纪元冻结的权重下进行**，否则就干脆不算。把一个旧得分重新缩放到
  新策略，会制造出一次从未发生过的比较；替代做法是把该节点标记为无效。

## 6. 陈旧、已失效、已移除、已删除 —— 四种不同的东西

「已删除」这个词在本词汇表中被禁用，因为这四种状态里有三种根本不涉及任何
删除。治理擦除**只是逻辑上的**：没有任何东西被物理删除或改写。证据仍留在
磁盘上；改变的是它是否被允许影响任何东西。

| # | 状态 | 实际发生了什么 | 它存在于哪里 | 可逆？ |
|---|---|---|---|---|
| 1 | **陈旧** | 某条记录由一个已退役组件产生，或实质性地依赖它。它不再参与前沿评分。 | 通过树持久化的增量节点哨兵字段（`_stale`、`_valid_for_frontier`、`_stale_reason`、`_erasure_event_id`），加上审计日志中的一次选择性擦除事件 | 可逆 —— 该记录及其溯源完好无损 |
| 2 | **已失效** | 该得分所依据的效用策略被取代，因此得分本身不再成立。 | 同一条哨兵通道，带一个不同的陈旧理由，加上擦除事件的失效节点列表 | 可逆 —— 基于幸存输入重算是一个正常结果 |
| 3 | **已移除** | 该节点被从搜索前沿中撤出（不再被展开）。 | 前沿重建事件列出被移除与被恢复的节点 | 可逆 —— 恢复是一个普通事件 |
| 4 | **物理删除** | 检查点目录及其日志已从磁盘上消失。 | 无 —— 这就是上述一切的缺席 | **不可逆** |

只有第四种是破坏，而它也是系统当作危险来对待的那一个操作：通过仪表盘删除
检查点会被拒绝，除非它携带一个服务器签发的、一次性使用的、绑定到那一条确切
路径的确认挑战，而且删除范围被限制在某个 `checkpoints/` 目录内部。

逻辑/物理分离在实践中的后果：

- 一个陈旧或已失效的节点仍然是**可审计的**。你仍然可以读到它做了什么、
  为什么被置为陈旧，以及是哪个事件把它置为陈旧的。这正是全部要点：撤回一个
  结果绝不能摧毁「曾经产生过它」的记录。
- 陈旧理由是**诊断性溯源**。它存在的意义是让人类 —— 或渲染标签的读模型 ——
  能说出一个节点*为什么*被置为陈旧；内核不会基于它做任何控制决策。
- **没有任何东西被追溯改写。** 既有运行绝不会为了获得治理而被修改，既有得分
  绝不会被重新缩放到新策略，而被取代的记录是被取代，不是被覆盖。

## 7. 词汇速查

| 术语 | 用它来表示 | 不要用它来表示 |
|---|---|---|
| 运行生命周期 | 进程是否存活 / 是否已结束 | 研究质量 |
| 研究阶段 | 在流水线中的位置（bfts / paper / review） | 治理进展 |
| 治理阶段 | 当前纪元 + 生效策略 | 研究的成功或失败 |
| 治理受阻 | 治理工件已降级或完整性校验失败 | 一次失败的实验或一次停止的运行 |
| 注册表状态 | 一个受治理组件的生命周期（candidate … banned） | 一个节点的得分 |
| 节点得分状态 | 单个节点的得分（computed … removed） | 一个组件的生命周期 |
| 原始攻击 | 一项未经裁决的对抗断言 | 任何数值 |
| 已验证惩罚 | 经过裁决、会影响得分的结果 | 攻击者所宣称的严重度 |
| 陈旧 / 已失效 / 已移除 | 逻辑状态，完全可审计 | 「已删除」 |
| 已删除 | 把一个检查点从磁盘上物理移除 | 任何治理状态 |
